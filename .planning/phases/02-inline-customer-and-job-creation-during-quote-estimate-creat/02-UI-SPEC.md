## Interaction Contracts

### Stacked Dialog Chain

```
Layer 0: Page (quotes list or estimates list)
Layer 1: CreateQuoteDialog / CreateEstimateDialog
Layer 2: CreateJobDialog (opened via "+ New job")
Layer 3: InlineCustomerForm dialog (opened via "+ New customer")
```

**Rules:**
1. Each dialog opens on top of the previous using Radix Dialog's native stacking (separate Dialog.Root instances).
2. Parent dialog remains mounted but visually obscured by child dialog overlay.
3. Closing a child dialog returns focus to the parent dialog. Parent form state is preserved.
4. Only closing the top-level dialog (Layer 1) discards all state.
5. ESC key closes only the topmost dialog, not the entire stack.
6. On mobile (below 768px), each dialog renders fullscreen per existing Quick task 260417-bwd pattern.

### Auto-Select After Inline Creation

| Action | Result |
|--------|--------|
| Customer created inline | Customer auto-selects in CreateJobDialog customer field. Job title auto-generates. |
| Job created inline | Job auto-selects in CreateQuoteDialog/CreateEstimateDialog job field. Customer auto-resolves from `job.customerId`. |

Pattern source: Quick task #9 (auto-select newly created job).

### Job Title Auto-Generation

Format: `{Job Type} - {Customer Name} #{N}`

Example: "Plumbing - John Smith #3"

The `#{N}` is derived by counting existing jobs for the same customer and incrementing by 1. If the customer has no prior jobs, N = 1.

The auto-generated title is NOT editable in the inline form. Users rename from the job detail page. This keeps the inline form minimal (2 fields: customer selector + job type dropdown).

### Form Field Specifications

**InlineCustomerForm (Layer 3):**

| Field | Type | Required | Validation | Placeholder |
|-------|------|----------|------------|-------------|
| Customer name | Text input | Yes | Non-empty, max 100 chars | "Customer name" |

**CreateJobDialog enhanced (Layer 2):**

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| Customer | Select + "+ New customer" action | Yes | Existing field, add action item |
| Job type | Select | Yes | Existing field, no changes |
| Job title | Hidden/auto | N/A | Auto-generated, not shown in form |

**CreateQuoteDialog / CreateEstimateDialog (Layer 1):**

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| Job | Select + "+ New job" action | Yes | Existing field, add action item |

### "+ New" Action Item Pattern

The "+ New job" and "+ New customer" actions appear as the last item in their respective Select/Combobox dropdowns.

| Property | Value |
|----------|-------|
| Position | Bottom of dropdown list, separated by a visual divider (`Separator`) |
| Icon | `Plus` from lucide-react (16px), positioned before text |
| Text color | `text-primary` (accent) |
| Text weight | 600 (semibold) |
| Hover | `bg-muted` background |
| Cursor | `pointer` |
| Behavior | Opens the corresponding inline creation dialog |

### Loading States

| Trigger | Loading indicator | Duration |
|---------|-------------------|----------|
| Creating customer | Button shows spinner, text changes to "Creating..." | Until API responds |
| Creating job | Button shows spinner, text changes to "Creating..." | Until API responds |
| Creating quote/estimate | Button shows spinner, text changes to "Creating..." | Until API responds |

### Success Feedback

| Action | Feedback |
|--------|----------|
| Customer created inline | Toast: "Customer created" (sonner, default duration). Dialog closes. Parent field populated. |
| Job created inline | Toast: "Job created" (sonner, default duration). Dialog closes. Parent field populated. |
| Quote/estimate created | Toast: "Quote created" / "Estimate created". Top-level dialog closes. Navigate to detail page. |

### Error States

| Error | Display | Recovery |
|-------|---------|----------|
| Customer name blank | Inline field error: "Customer name is required" | Fix and resubmit |
| Customer creation API error | Toast: "Could not create customer. Please try again." | Retry from same form |
| Job creation API error | Toast: "Could not create job. Please try again." | Retry from same form |
| Quote/estimate creation API error | Toast: "Could not create quote. Please try again." / "Could not create estimate. Please try again." | Retry from same form |
| Network error | Toast: "Connection error. Check your internet and try again." | Retry |

### RTK Query Cache Invalidation

When an entity is created inline, the parent selector must reflect the new entity:

| Mutation | Tags Invalidated |
|----------|-----------------|
| Create customer | `Customers` list tag (so job dialog customer selector refreshes) |
| Create job | `Jobs` list tag (so quote/estimate dialog job selector refreshes) |
| Create quote | `Quotes` list tag |
| Create estimate | `Estimates` list tag |

The auto-select pattern does NOT rely on cache invalidation for immediate selection -- the newly created entity is passed directly via callback (`onCustomerCreated`, `onJobCreated`). Cache invalidation ensures the list is up-to-date if the user reopens the selector.

## Mobile Behavior

## Accessibility

| Concern | Implementation |
|---------|---------------|
| Focus trap | Each Radix Dialog traps focus within itself. Stacked dialogs transfer trap to topmost. |
| ESC behavior | Closes topmost dialog only (Radix default). |
| Screen reader | Dialog titles announced via `DialogTitle`. Form errors associated via `aria-describedby`. |
| Keyboard nav | Tab order within each dialog. "+ New" actions reachable via keyboard in select dropdowns. |
| Touch targets | All interactive elements minimum 44px touch target on mobile. |
